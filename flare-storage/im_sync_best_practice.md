# IM 初始化与重连同步最优方案（工业级）

## 一、目标

实现： - 秒开（低延迟） - 不丢消息（强一致） - 多端一致 -
可扩展（支持万级数据）

------------------------------------------------------------------------

## 二、核心思想

> 初始化同步 = Snapshot（状态） + Event（变化）

并对 Event 做"分级处理"。

------------------------------------------------------------------------

## 三、事件分级策略

### 1. 必须回放（强一致）

-   EVENT_MESSAGE_RECALL
-   EVENT_MESSAGE_EDIT
-   EVENT_MESSAGE_DELETE
-   EVENT_CONVERSATION_UPDATE
-   EVENT_CONVERSATION_DELETE
-   EVENT_PIN / UNPIN
-   EVENT_MARK / UNMARK

说明： - 影响最终状态 - 必须参与 seq 补齐

------------------------------------------------------------------------

### 2. 可聚合（优化性能）

-   EVENT_READ_RECEIPT
-   EVENT_REACTION

策略： - 不逐条回放 - 服务端聚合为最终结果

示例：

``` json
{
  "msgId": "xxx",
  "readCount": 10
}
```

------------------------------------------------------------------------

### 3. 不回放（瞬时事件）

-   EVENT_TYPING
-   EVENT_PRESENCE
-   EVENT_CALL_SIGNAL

策略： - 登录后重新订阅 - 不参与历史同步

------------------------------------------------------------------------

## 四、初始化同步流程（第一次登录）

### Step 1：Snapshot（轻量）

``` json
{
  "conversations": [...前50条],
  "messages": [...每个会话最新20条],
  "snapshotSeq": 10000
}
```

特点： - 只给用户"当前可见数据" - 不返回历史全量

------------------------------------------------------------------------

### Step 2：关键事件回放

``` json
[
  { "seq": 10001, "type": "delete" },
  { "seq": 10002, "type": "edit" }
]
```

只回放： - 删除 / 编辑 / 撤回 / 会话变更

------------------------------------------------------------------------

### Step 3：实时订阅

-   WebSocket 推送所有事件

------------------------------------------------------------------------

### Step 4：后台分页加载

-   历史消息按需加载
-   用户无感知

------------------------------------------------------------------------

## 五、断线重连 / 再登录

请求：

GET /sync?fromSeq=lastSeq

------------------------------------------------------------------------

### 服务端优化

1.  事件压缩
    -   多次 edit → 保留最后一次
    -   delete 覆盖 edit
2.  会话聚合

``` json
{
  "convId": "xxx",
  "lastMsg": "...",
  "unread": 10
}
```

------------------------------------------------------------------------

## 六、客户端处理

### 1. 应用 snapshot

applySnapshot()

------------------------------------------------------------------------

### 2. 回放事件（幂等）

if (event.seq \<= lastSeq) return

------------------------------------------------------------------------

### 3. ACK

ack(lastSeq)

------------------------------------------------------------------------

### 4. 分批更新 UI

batchApply(events, 50)

------------------------------------------------------------------------

## 七、删除设计

删除必须作为事件：

``` json
{
  "seq": 10002,
  "type": "delete",
  "msgId": "xxx"
}
```

说明： - 不物理删除 - 保证 seq 连续

------------------------------------------------------------------------

## 八、服务端架构建议

-   Message 表（当前状态）
-   Event Log（完整事件流）
-   Snapshot 定期生成

------------------------------------------------------------------------

## 九、一句话总结

> IM 同步的本质不是"拉数据"，而是"恢复状态 + 回放变化"

------------------------------------------------------------------------

## 十、最佳实践总结

-   Snapshot 控制体积（只给可见数据）
-   Event 分级处理（不是全回放）
-   seq 保证一致性
-   ACK 保证可靠性
-   WebSocket 保证实时性
